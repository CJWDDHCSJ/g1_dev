# P0-20 语音动作触发与业务闭环（阶段摘要）

- **时间**：2026-11-02
- **完整报告**：
  - [P020_ACTION_INTERACTION_REPORT.md](P020_ACTION_INTERACTION_REPORT.md)

- **结论**：语音口令第一次真正驱动 G1 手臂动作并形成业务闭环（请求 → 执行 → 结果 → 语音反馈），且只对白名单动作开放。

## 一、模块拆分（P0-20）

| 决策 | 原因 |
|---|---|
| 动作执行独立成 `g1_action_executor` 包 | 含 FSM/模式/手臂检查与同步 RPC，不能与语音业务挤在一个进程 |
| 用话题而非服务 | 请求是事件流，且结果需要异步等待；服务调用会阻塞 Router 的单一 worker |
| 结果用字符串协议 | 与既有实现兼容，改造成本最低（代价：无请求 ID） |

## 二、安全设计

1. `ActionCommandMapper`：禁用表达 → 否定 → 疑问 → 最长短语 → 出口白名单校验；
2. 永久禁用 `hand_on_heart` / ID 33；
3. 执行器前置检查：FSM ∈ {500,501,801}、`victory`/`heart` 需 `mode_machine ∈ {5,6}`、`holding == false`、`id == 0`、非 busy、冷却 ≥3 s；
4. 执行超时：开始 5 s / 完成 30 s / 稳定 3 s（最坏约 38 s），Router 等 45 s；
5. 失败锁定：不确定完成状态时不释放 busy，要求人工确认。

## 三、Mock 验证（P0-20）

覆盖：成功、失败、拒绝、超时、禁用、去重、队列满顺序。`ActionCommandMapper` 39 项、`InteractionManager` 76 项全绿。

## 四、生产切换与真机验收（P0-20.1）

| 项目 | 结果 |
|---|---|
| 非动作回归 | 自我介绍、实验室介绍、电量、动作状态、运行状态 5 项正确，`ACTION_SENT` = 0 |
| 单次 wave | `request_id=7`，`accepted:wave:26` → 约 13 s → `success:wave:26`，现场确认挥手 |
| 整体状态播报 | 131 字节、4 句，含真实 BMS 电量“百分之93” |
| 忙碌提示顺序 | 修复为“所有已接受请求处理完才播报” |

## 五、遗留

- 仅 `wave` 完成真机验收，其余 5 个动作只有白名单与 Mock；
- 结果无请求 ID，同名动作理论上可能误配延迟结果；
- `completion_unknown` / `completed_with_rpc_error` 前缀 Router 不识别，会退化为 45 s 超时提示。

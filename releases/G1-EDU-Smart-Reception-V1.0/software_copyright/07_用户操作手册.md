# 07 用户操作手册

## 1. 系统启动

1. 开启 G1，等待 45 秒左右，5 个服务自动启动。
2. 检查：`systemctl --user is-active g1-voice-stack.target` 应返回 `active`。
3. 机器人站立稳定后即可开始对话。

## 2. 系统状态检查

```bash
for s in g1-robot-state-provider g1-tts g1-voice-router g1-asr-bridge g1-action-executor; do
  printf '%s %s\n' "$s" "$(systemctl --user show -p ActiveState --value $s.service)"
done
ros2 topic echo /g1/robot_state --once
```

## 3. 语音问答

- 站在机器人前方 0.5–1.5 米，正常语速清晰说话。
- 一次问一个问题，等机器人播报完再问下一个。
- 若未识别，可换更完整的说法（例如把"脑机接口"说完整，或说"介绍一下脑机接口"）。
- 连续快速提问时，机器人会提示"我现在要回答的问题有点多，请你稍等一下"。

示例：

| 说法 | 预期 |
|---|---|
| 你好 | 固定问候（并挥手） |
| 介绍一下你自己 | 本地固定自我介绍 |
| 介绍一下我们实验室 | 本地知识库介绍 |
| 脑机接口是什么 | 外部模型通用知识回答 |
| 宇树 G1 多少钱 | 明确拒绝报价 |

## 4. 电量查询

说："你现在还有多少电量" / "电池电量是多少"。
回答示例："我的电池电量大约是百分之 93。"
数据来源为机器人 BMS 实时数据；若数据过期会说明"数据已一段时间未更新"。

## 5. IMU 数据接收查询

说："你现在的 IMU 数据接收情况怎么样" / "IMU 数据还在更新吗"。
回答示例："我目前能够持续接收到 IMU 数据，但还没有完成完整的传感器健康诊断。"
注意：系统只回答**数据接收与时效**，不做传感器健康结论。

## 6. 实验室介绍

说："介绍一下我们实验室" / "实验室有哪些设备" / "实验室主要研究什么"。
资料来源于本地知识库（含官方公开来源）；没有核实资料时会明确说明"暂无经过核实的公开资料"。

## 7. 动作命令

支持的白名单动作（说出口令即可）：

| 口令示例 | 动作 |
|---|---|
| 挥个手 / 挥挥手 | wave |
| 轻轻挥手 / 低位挥手 | wave_low |
| 举手 / 举起双手 | hands_up |
| 拍个手 / 鼓掌 | clap |
| 比个心 | heart |
| 比个耶 / 剪刀手 | victory |

说明：
- 每条口令只执行一次；执行完成会播报"好的，X 动作完成了"。
- "不要挥手""别举手""停止动作"不会执行任何动作。
- "挥手的原理是什么"属于知识问答，不会执行动作。
- "你会做哪些动作"只介绍能力，不执行动作。
- 若提示"动作执行结果暂时没有收到，我不会自动重复执行"，请勿重复下口令，先检查执行器状态。

## 8. 异常处理

| 现象 | 处理 |
|---|---|
| 无任何回复 | 检查 5 个服务是否 active；检查是否有两个 Router 进程 |
| 回答"无法连接对话模型" | 检查笔记本 Ollama 是否运行、网络是否连通 |
| 状态回答为"无法确认" | 检查 `/g1/robot_state` 是否有数据、`status` 是否 VALID |
| 动作不执行 | 查看 action_executor 日志中的 FSM/Arm State；确认手臂周围安全 |
| 播报重复 | 立即停止服务，检查是否启动了第二份 Router |
| 需要紧急停止动作 | 现场人员扶稳机器人并执行 `systemctl --user stop g1-action-executor.service` |

## 9. 系统停止

```bash
systemctl --user stop g1-voice-stack.target
```

单节点重启（推荐）：

```bash
systemctl --user restart g1-voice-router.service
```

## 10. 演示前检查清单

1. 五服务 active、Router 进程唯一
2. `/g1/robot_state` 的 `battery.status` 为 VALID 且电量 > 30%
3. 机器人站立稳定、手臂周围 1 米无障碍
4. 现场有人可随时停机
5. 演示台词避免使用未验证动作名

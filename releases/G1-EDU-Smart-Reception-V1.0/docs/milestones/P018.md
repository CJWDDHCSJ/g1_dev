## 一、RobotStateProvider（P0-18）

| 项目 | 实现 |
|---|---|
| 订阅 | `/lowstate`、`/sportmodestate`、`/arm/action/state`、`/lf/bmsstate`，全部 BEST_EFFORT / KeepLast(1) |
| 发布 | `/g1/robot_state`，2 Hz（500 ms 定时器） |
| 判定 | 每字段 `VALID / STALE / UNAVAILABLE / INVALID`，带 `received_age_ms` 与 `quality_reason` |
| 时效 | lowstate/sportmode/arm 1000 ms、bms 2000 ms |
| SOC | 只用 BMS `soc`；范围校验 + 60 s 内 ≥15% 跳变判 `INVALID` |
| 序列化 | 非 `VALID` 的数值输出 `null`，不用 0 伪装 |

## 二、生产部署（P0-18.1）

- Provider 与 Router 同源构建，部署后 `/proc/<pid>/exe` 指向 install 下的二进制；
- 真机抓到聚合 JSON（如 `"battery":{"status":"VALID","soc_percent":49,...}`），证明数据链路可用；
- 当次回归：`colcon test` 报告 4 个测试目标全绿，各套件直跑 44/75/119/57 全过。

## 三、systemd 服务化（P0-18.2）

| 项 | 值 |
|---|---|
| 服务数 | 5 个 business service + `g1-voice-stack.target` |
| 重启策略 | `Restart=always`、`RestartSec=3` |
| 停机 | `KillSignal=SIGINT`、`TimeoutStopSec=15` |
| 限流 | `StartLimitIntervalSec=60`、`StartLimitBurst=5` |
| 依赖 | `PartOf=target`、`After=` 表达先后 |
| 权限 | 全部以 `unitree` 用户运行，无 root 依赖 |

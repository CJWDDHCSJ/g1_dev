# 04 模块功能说明

## 1. AsrTextNormalizer（ASR 文本归一化）

- 文件：`src/asr_text_normalizer.cpp`、`include/g1_voice_router/asr_text_normalizer.hpp`
- 输入：原始 ASR 文本；输出：`AsrNormalization{raw_text, normalized_text, changed, rule_id, reason}`
- 规则（有限、有证据）：
  - `ASR001_BRAIN_COMPUTER_INTERFACE`：`脑急接口` → `脑机接口`
  - `ASR002_UNITREE_G1`：`语数之一/语数G1` → `宇树G1`（**仅当**文本含机器人/宇树/价格/型号等上下文）
- 保护逻辑：含 `不要/别/停止/取消/不准/不许` 时整体跳过；不碰数字；原始文本始终保留。
- 日志：`event=ASR_NORMALIZED rule=… raw_len=… raw_digest=… normalized=…`（不打印完整原始语音）。

## 2. InteractionManager（交互任务管理）

- 文件：`src/interaction_manager.cpp`、`src/interaction_filter.cpp`
- 功能：空文本/噪声过滤、同一文本去重（时间窗）、有界 FIFO（默认等待上限 3）、请求状态机、`pending_count()` 供调度判断。
- 去重缓存有界：条目 ≥64 或每 32 次提交清理过期记录（窗口×2）。
- 状态转移严格校验：`ACTION_WAITING` 只允许转向 `REPLY_READY/COMPLETED/FAILED/TIMEOUT`。

## 3. IntentRecognizer（意图识别）

- 文件：`src/intent_recognizer.cpp`
- 意图：GREETING、GOODBYE、LAB_INTRO、ROBOT_INTRO、DEMO_ACTION、ROBOT_STATUS、GENERAL_QA 等。
- 判定顺序要点：价格/动作命令 → 知识问法豁免（`是什么/如何/原理`，但含"当前/现在/目前"时不豁免）→ 实验室实体 → 机器人状态（含 IMU 数据接收问法）→ 兜底状态词。
- 96 项单元测试锁定语义边界（含"机器人如何判断自己的运行状态"→GENERAL_QA、"实验室当前状态怎么样"→LAB_INTRO）。

## 4. KnowledgeBase（本地知识库）

- 文件：`src/knowledge_base.cpp`、`config/lab_knowledge.json`
- 数据：FAQ 21 条、研究方向 3、项目 1、设备 1、分类 5、实验室 3、来源 15。
- 能力：结构化字段检索 + FAQ 相似度、实体掩码、意图相容判断、同分安全兜底。
- 输出：`found/answer/match_type/matched_id/match_score`，未命中明确兜底。

## 5. FactRiskGuard（事实风险保护）

- 文件：`src/fact_risk_guard.cpp`
- 风险类型：`PRICE`、`REALTIME_STATUS`、`LAB_FACT`、`NORMAL`。
- 处理：PRICE 直接兜底；REALTIME_STATUS 直接兜底；LAB_FACT 先查知识库，可靠命中才用本地答案，否则兜底；NORMAL 放行至 Ollama。
- 规则只增不删，作为 IntentRecognizer 的第二道防线。

## 6. RobotStateProvider / RobotStateEvaluator（状态感知与回答）

- 文件：`src/robot_state_provider.cpp`、`src/robot_state_provider_node.cpp`、`src/robot_state_evaluator.cpp`
- 订阅：`/lowstate`、`/sportmodestate`、`/arm/action/state`、`/lf/bmsstate`（`/dog_odom` 未接入）
- 输出：`/g1/robot_state`（`schema_version=1` 聚合 JSON，2 Hz），每类字段带 `status/quality_reason/received_age_ms/source_topic`
- 有效性：VALID / STALE / UNAVAILABLE / INVALID，分话题差异化超时
- 回答：电量、IMU 数据接收（明确"未完成完整传感器健康诊断"）、动作执行状态、整体运行状态

## 7. ActionCommandMapper（动作命令映射）

- 文件：`src/action_command_mapper.cpp`
- 白名单：wave 26、wave_low 25、hands_up 15、clap 17、heart 20、victory 30
- 判定顺序：永久禁用（hand_on_heart/33）→ 否定/停止 → 疑问/能力询问 → 最长短语匹配
- 二次校验：出口必须命中 `whitelist_id()`，任何路径不输出白名单外 ID

## 8. TTS 输出（g1_tts_node）

- 订阅 `/g1/tts`，调用 `AudioClient::TtsMaker(sentence, speaker_id)`，中文分句、逐句发送、按字数估算播放时长并插入 `pause_ms`（默认 1500ms）。
- 配置：`~/unitree_ros2/example/config/tts_config.json`（speaker_id=0、volume=80）。

## 9. Action Executor（g1_action_executor）

- 订阅 `/g1/action_request`（规范动作名），执行前检查 FSM(501)、mode_machine、Arm State 空闲；内部超时：启动 5s、完成 30s、动作后稳定 3s。
- 结果格式：`accepted:<name>:<id>`、`success:<name>:<id>`、`failed:<name>:<id>`、`timeout:…`、`rejected: <原因>`。

## 10. Ollama 接口

- `POST http://<LLM_HOST>:11434/api/chat`，`model=qwen3-vl:4b-instruct`，`stream=false`，`temperature=0.2`，`num_predict=160`
- 连接超时 3s，整体超时由参数控制；请求历史保留最近 6 轮；失败播报固定兜底，不重试。

## 11. systemd 生命周期与日志

- 5 个 user service + target；`Restart=always`、`KillSignal=SIGINT`、`TimeoutStopSec=15`；开机自恢复。
- 日志按日轮转，磁盘检查服务定期执行。

# 02 软件设计说明书

## 1. 设计目标

在 G1-EDU 真机上构建一个可演示、可解释、可安全控制的实验室智能接待系统：语音输入 → 意图理解 → 业务分流（本地知识库 / 本地状态 / 外部大模型 / 动作执行）→ 语音输出，并在任何异常下都不编造事实、不误触发动作。

## 2. 设计原则

1. **本地优先**：能用本地数据回答的，不交给大模型。
2. **程序性安全**：事实约束以代码规则实现，提示词仅作辅助。
3. **串行化交互**：一次只处理一条请求，回复顺序严格等于请求顺序。
4. **白名单控制**：动作、价格、状态均不允许自由生成。
5. **可测试性**：每个判定模块都是纯 C++ 独立库，可脱离 ROS 单测。
6. **证据可追溯**：日志保留 request_id、规则命中、原始文本摘要。

## 3. 系统总体架构

                                                    g1_voice_router
                                             ┌──────────────────────┐
                                             │ AsrTextNormalizer    │
                                             │ InteractionManager   │
                                             │ IntentRecognizer     │
                                             │ 业务分流             │
                                             └──────────────────────┘
        ┌────────────┬──────────────┬──────────────┬──────────────┐
        ▼            ▼              ▼              ▼              ▼
   GREETING     ROBOT_STATUS    LAB_INTRO      GENERAL_QA     DEMO_ACTION
   +动作请求     RobotState      KnowledgeBase  FactRiskGuard  ActionCommandMapper

## 4. 主要数据结构

| 结构 | 作用 |
|---|---|
| `InteractionRequest` | 一条交互任务：request_id、文本、状态、时间戳 |
| `InteractionStatus` | RECEIVED/QUEUED/FILTERED/DUPLICATE/REJECTED/PROCESSING/WAITING_OLLAMA/ACTION_WAITING/REPLY_READY/COMPLETED/FAILED/TIMEOUT |
| `IntentResult` | 意图枚举 + 命中关键词 |
| `KnowledgeResult` | found、answer、match_type、matched_id、match_score |
| `FactRiskResult` | risk、blocked、use_local_answer、reason、fallback_answer |
| `ActionCommand` | matched、action_name、action_id、match_type、reject_reason |
| `AsrNormalization` | raw_text、normalized_text、changed、rule_id |
| `AggregatedRobotState` | battery/imu/runtime/action/odom 各自的 `FieldState`（status、age、quality_reason） |

## 5. 关键流程设计

### 5.1 请求准入（ROS 回调线程，轻量）

`trim → AsrTextNormalizer → 过滤（空/过短/噪声）→ 去重（同文本窗口内拒收）→ 有界队列（满则拒绝最新）`。回调不执行业务、不发布 TTS。

### 5.2 请求处理（唯一 worker 线程）

按意图顺序判定并**提前返回**：

1. GREETING（本地固定问候 + 动作请求）
2. ROBOT_STATUS（本地 RobotStateProvider 聚合回答）
3. DEMO_ACTION（白名单映射 → 动作执行 → 等待结果 → 反馈）
4. LAB_INTRO（知识库可靠命中则本地回答，否则安全兜底）
5. ROBOT_INTRO / GOODBYE（本地固定文本）
6. GENERAL_QA（FactRiskGuard → 拦截兜底 / 本地答案 / Ollama）

### 5.3 动作执行

`ActionCommandMapper` 输出规范动作名 → 发布 `/g1/action_request` → 等待 `/g1/action_result`（按动作名 + 发送前序号快照匹配，45s 超时）→ SUCCESS/FAILED/TIMEOUT/REJECTED 四类反馈。**不确定时不重试**。

### 5.4 停机

`SIGINT → shutdown_requested_ → action_result_cv_.notify_all + curl 进度回调中止 → manager.stop() → worker join`。实测三种场景均 < 1s 退出。

## 6. 异常与降级设计

| 异常 | 处理 |
|---|---|
| Ollama 不可达/超时 | 播报"暂时无法连接对话模型"，不重试，正常处理下一条 |
| 知识库未命中 | 播报"暂无经过核实的公开资料" |
| 状态数据 STALE | 播报"数据一段时间未更新" |
| 状态数据 UNAVAILABLE | 播报"暂时无法确认" |
| 动作结果缺失 | 播报"未收到结果，不会自动重复执行" |
| 队列满 | 拒绝最新请求，worker 在已接受请求完成后播报忙碌提示 |
| Provider 未启动 | ROBOT_STATUS 全部走安全兜底 |

## 7. 安全设计

1. 动作白名单硬编码，二次校验，`hand_on_heart`/ID 33 永久禁用。
2. 价格类问题永不交给模型生成数字。
3. 否定/停止/取消表达永不触发动作，且归一化层整体跳过。
4. 动作 Result 与请求不同名时不接受，等待超时。
5. 单 Domain 只允许一个 Router（避免重复动作请求）。

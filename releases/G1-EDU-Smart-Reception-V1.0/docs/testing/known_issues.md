# 已知问题与限制

按“影响程度 / 是否可绕过”排序。

## 1. ASR 专有名词误识（中，部分可绕过）

- 现象：`脑机接口` 被识别为 `脑急接口` / `脑筋接口` / `手机接口`；`宇树G1` 曾被识别为 `语数之一`。
- 已处理：前两类加 `ASR001` 别名；`语数之一` 加 `ASR002`（需机器人上下文）。
- 未处理：`手机接口` 属合法词组，**故意不做映射**。
- 绕过：说更完整的句子，或分字清晰发音。

## 2. 动作结果没有请求 ID（中，靠串行规避）

- 协议为 `success:<name>:<id>`，无关联 ID。
- 当前策略：单 worker 串行 + 动作名匹配 + 发送前序号快照 + 45s 超时 + 不重试。
- 风险：同名动作连续执行时，理论上可能误配延迟到达的旧结果。
- 根治：给执行器结果协议加请求 ID（V1.0 之后）。

## 3. 不支持并发动作（设计限制）

所有动作在 worker 内串行等待；一次只能有一个动作在途。多动作请求会排队，总耗时线性增长。

## 4. IMU 只回答“接收与时效”（设计限制）

`data_available=true` 只代表持续收到消息，不代表传感器健康、姿态估计准确。问“IMU 是否健康”时回答会明确说明“未完成完整的传感器健康诊断”。

## 5. TTS 无播放完成事件（中）

`TtsMaker ret=0` 仅代表调用成功；句间等待是按字数估算 + `pause_ms=1500`。因此“播报完成”无法精确感知，长句可能被下一次播报挤压。

## 6. 动作真机覆盖不足（中）

仅 `wave` 有完整真机验收记录；其余 5 个动作只有白名单登记与 Mock 测试。

## 7. 外部模型依赖（中）

模型运行在机器人外部主机上；断网时只有本地能力（知识库、状态、动作、固定话术）可用，`GENERAL_QA` 会播报“暂时无法连接对话模型”。

## 8. 状态字段覆盖有限（低）

电池/IMU/运行/动作四组可用；关节温度、电机电流、里程计等字段虽在原始话题中存在，但**单位与索引映射未确认**，未用于对外回答。

## 9. 单进程业务（低）

Router 是单点：崩溃会中断全部业务（systemd 在 3s 后拉起，期间请求丢失）。

## 10. 知识库覆盖有限（低）

FAQ 21 条、方向 3、项目 1、设备 1；未收录问题统一兜底“暂无经过核实的公开资料”。不猜测、不调用模型补答。

## 11. 队列容量小（低）

等待上限 3；高峰时新请求会被拒绝并提示“问题有点多”，需要重说。
